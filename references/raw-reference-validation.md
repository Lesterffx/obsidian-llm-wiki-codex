# 媒体引用修复：Markdown 规则与验证案例

本文件补充 `SKILL.md` 的 `update-raw-reference` 工作流，不是独立转换程序。所有示例均为虚构；验证产物留在仓库外，不提交真实页面、素材、manifest 或日志。

## 输入与转换规则

第一参数为目录时，先执行[共用目录批量规则](directory-batch.md)：只处理直属 `.md`，按完整同名 raw 子目录配对，缺失则整页跳过；整批预检先于任何写入。下列媒体匹配规则只在各页已确认的有效 raw 子目录内应用，不能把批次 raw 根目录当作媒体候选目录。文件输入保持原行为。

- Obsidian 媒体嵌入、Markdown 图片和 raw PDF 附件链接共享同一份按正文顺序建立的 manifest。记录完整原表达式及字节位置，先判断上下文再解析；不要用单个全局正则替换整篇 Markdown。所有既有章节均保留，记录引用替换的原始字节跨度。
- Obsidian `![[...]]` 的图片、视频、音频扩展名及 `#fragment`、`|alias/width` 规则不变；文件名中的 `%20` 等按字面值匹配，不新增 URL 解码。
- Markdown 分支处理 inline 本地图片，以及正文中指向 raw 的 inline PDF 附件链接（扩展名大小写不敏感）。支持中文、百分号编码的空格、`<...>` 包裹的含空格目标、合法反斜杠标点转义、成对括号，以及单引号、双引号或括号包裹的纯文本 title。未包裹且含未编码空格的目标按不安全语法跳过，不猜测空格属于路径还是 title。
- 先解析表达式、Markdown 标点转义、目标与可选 title，再分离未编码的 `#fragment`。对路径做一次严格 UTF-8 百分号解码；不把 `+` 当空格，不二次解码，不修改实际文件名大小写或 Unicode 形式。非法编码、编码的路径分隔符、控制字符，以及无法无损写入 Obsidian 目标的字符（如实际文件名中的 `#`、`|`、`[`、`]`）保持原样并报告。fragment 只在无需改写即可安全保留时转换，否则跳过。
- 仅接受可解释为 vault 内本地路径的目标；相对路径按页面目录解释，显式 `raw/...` 按 vault 根目录解释。失效旧路径仍可按文件名匹配指定目录，但不能越出 vault。拒绝盘符、UNC、根绝对路径及带 URI scheme 的目标；外部 URL、协议相对 URL、data URI、带未编码查询串的目标不下载、不改写。解码后再次检查这些边界。
- 按实际文件名匹配指定 raw 目录的直属文件，不搜索子目录、不推测改名。候选必须唯一且真实路径仍在该目录内；已有显式路径有效指向其他 raw 目录时保留并报告。完整正确的 Markdown 目标仍转换语法；完整正确的 Obsidian 目标为 no-op。
- PDF 链接还须确认规范化后的旧目标位于 raw 内；不存在的旧 raw 路径可以按原文件名匹配指定目录，非 raw 本地 PDF 链接不扩展处理。相对路径按页面目录解释，`raw/...` 按 vault 根目录解释；匹配只查指定目录直属文件，已有有效其他 raw 路径不重定向。PDF 转换复用上述一次解码、安全片段和可表示目标规则，不读取 PDF 内容、不预处理或上传文件。
- 引用式图片/附件链接（完整、折叠、快捷）、HTML、除上述 raw PDF 附件外的普通链接、被外层链接包裹的图片，以及包含嵌套格式或多行 alt/link text/title 的表达式保持原样并报告，不修改引用定义。frontmatter、代码、注释及转义后的示例不作为待转换引用。

## PDF 附件链接嵌入化

仅在 `update-raw-reference` 执行时，把页面已有、逐条确认的 raw PDF 链接整体替换为 `![[raw/<完整目录>/<实际文件名>#fragment]]`；没有片段时省略。实际文件名来自唯一匹配的 raw 文件，保留中文、空格、大小写和扩展名，不使用页面标题、链接显示文字或 title 命名。`讲义.pdf` / `handout.pdf` 只在真实文件同名时使用，不能作为固定输出名。已有合规的完整路径 PDF 嵌入（含安全片段或显示参数）不动，不把其他 PDF 嵌入扩大为媒体修复对象。

同页多个 PDF 按各自目标独立匹配；相同显示文字不代表相同附件。重复链接仍保留每次出现的位置和片段，不能合并、交换、套用前一条的文件名或按目录枚举顺序配对。raw 目录中未被页面引用的 PDF 不插入。原文件名缺失或歧义时，即使只有一个其他 PDF，也保持原表达式并报告；误写的 `讲义.pdf` 同样不猜测改名，不移动或重命名 raw 文件。

```text
[讲义](<../../raw/示例/资料/课程说明.pdf>)
→ ![[raw/示例/资料/课程说明.pdf]]

[讲义](<raw/示例/资料/练习题.pdf#page=3> "阅读材料")
→ ![[raw/示例/资料/练习题.pdf#page=3]]

[再次下载](<raw/示例/资料/课程说明.pdf#page=2>)
→ ![[raw/示例/资料/课程说明.pdf#page=2]]
```

原链接文字和可选 title 随原表达式从页面消失，逐项保留在报告中，不生成可见说明、图片说明或任何新内容节。实际转换刷新 `updated`；缺失、歧义、越界或不安全表达式保留并报告。以下图片说明规则仅用于原有 Markdown 图片分支，不套用到 PDF。

## 既有章节保留

`update-raw-reference` 保留所有既有内容章节，包括「总结」「洞察」「资料总结」「洞见」及其他标题。无论章节是否相邻、重复、包含子标题、位于 EOF，或是否含图片和链接，都不得据此删除、改写、移动或替换；不凭标题或疑似抓取来源推断原文可以清理。

章节内符合规则的媒体和 raw PDF 引用仍可原位修复；除已记录的引用替换及 frontmatter 窄例外外，其余字节均不变。本命令不生成或追加总结、洞察、替代说明或任何内容章节。Markdown 图片转换已有的紧邻说明文字规则不变。

仅存在这些章节不构成实际变化。没有其他引用转换、缺字段修复或必要索引补录时，页面、updated、index、日志和队列均保持无操作；无需报告拒删或请求章节清理裁定。原始换行及末尾换行状态必须保持，没有删除至 EOF 的例外。

## 说明文字保留

纯文本 alt 经 Markdown 转义还原后，若为空或仅等于原目标文件名或一次解码后的实际文件名，则不新增说明；比较时仅忽略两端空白，不做模糊匹配。其他 alt 都视为有意义的说明。非空 title 始终保留，即使与 alt 相同，也保留其标题身份。

转换后在嵌入后立即添加 `（图片说明：…；标题：…）`；仅有一项时只保留对应字段，两项都没有时不添加括号。保留纯文本含义和内容，必要时转义 Markdown 元字符以避免意外标签、链接、嵌入或格式；遇到不能可靠解释的实体或富文本时跳过整个表达式并报告，不猜测或丢弃。不向 `|宽度/别名` 填入说明，不改变已有相邻正文。

```text
![流程概览](旧附件/diagram.png "步骤说明")
→ ![[raw/示例/资料/diagram.png]]（图片说明：流程概览；标题：步骤说明）

![diagram\.png](旧附件/diagram.png)
→ ![[raw/示例/资料/diagram.png]]
```

原来的 alt 可访问性属性与 title 悬停属性会转为可见文字，语义内容保留，呈现方式改变；不声称 Obsidian 嵌入仍有相同的 HTML 属性。

## 单项验收案例

假设指定目录为 `raw/示例/资料/`，表中成功案例所需的直属文件均存在；`missing.png` 不存在，`raw/示例/其他/diagram.png` 已存在。下表是人工工作流验收预期，不是自动化测试通过记录。

| 情形 | 原表达式 | 预期 |
|---|---|---|
| Markdown 文件名 alt | `![diagram\.png](旧附件/diagram.png)` | `![[raw/示例/资料/diagram.png]]` |
| 空 alt | `![](旧附件/diagram.png)` | `![[raw/示例/资料/diagram.png]]` |
| 中文与编码空格 | `![示例 图.png](旧附件/示例%20图.png)` | `![[raw/示例/资料/示例 图.png]]` |
| 尖括号路径 | `![](<旧附件/示例 图.png>)` | `![[raw/示例/资料/示例 图.png]]` |
| 转义括号 | `![](旧附件/plot\(a\).png)` | `![[raw/示例/资料/plot(a).png]]` |
| 成对括号 | `![](旧附件/plot(a).png)` | `![[raw/示例/资料/plot(a).png]]` |
| 仅解码一次 | `![](旧附件/literal%2520name.png)` | 匹配实际 `literal%20name.png`，不匹配 `literal name.png` |
| 加号 | `![](旧附件/a+b.png)` | 匹配实际 `a+b.png`，不匹配 `a b.png` |
| 仅说明 | `![流程概览](旧附件/diagram.png)` | `![[raw/示例/资料/diagram.png]]（图片说明：流程概览）` |
| 仅标题 | `![](旧附件/diagram.png '步骤说明')` | `![[raw/示例/资料/diagram.png]]（标题：步骤说明）` |
| 说明和标题 | `![流程概览](旧附件/diagram.png "步骤说明")` | 两项各保留一次，采用上方示例格式 |
| 括号标题 | `![](旧附件/diagram.png (步骤说明))` | `![[raw/示例/资料/diagram.png]]（标题：步骤说明）` |
| fragment | `![](旧附件/diagram.svg#overview)` | `![[raw/示例/资料/diagram.svg#overview]]` |
| 原有宽度 | `![[diagram.png\|800]]` | `![[raw/示例/资料/diagram.png\|800]]`，宽度不变 |
| 原有别名和片段 | `![[diagram.svg#overview\|概览]]` | 路径补全，`#overview\|概览` 不变 |
| 视频、音频 | `![[clip.mp4]]`、`![[sound.mp3]]` | 两者均补全 raw 路径，顺序不变 |
| 已有完整目标 | `![[raw/示例/资料/diagram.png]]` | 不变；同目标 Markdown 图片仍转换语法 |
| 别处的有效目标 | `![](raw/示例/其他/diagram.png)` | 不变并报告，不能因本目录同名而重定向 |
| 文件缺失或歧义 | `![](旧附件/missing.png)` 或多个可能候选 | 不变并报告，不猜测 |
| 外链 | `![](https://example.invalid/diagram.png)` | 不变并报告，不访问网络 |
| 引用式 | `![说明][figure]`、`![figure][]`、`![figure]` | 不变，定义不变 |
| HTML | `<img src="旧附件/diagram.png">` | 不变并报告 |
| 外层链接 | `[![说明](旧附件/diagram.png)](目标)` | 整体不变并报告 |
| 复杂说明 | `![**重点**](旧附件/diagram.png)` | 不变并报告，不丢弃格式 |
| 编码异常 | `![](旧附件/bad%ZZ.png)`、`![](旧附件/a%2Fb.png)` | 不变并报告 |
| 不可表示文件名 | `![](旧附件/a%23b.png)` | 不变并报告，不误判成 fragment |

表格中的 `\|` 是 Markdown 表格转义；构造真实正文样例时使用普通 `|`。代码区、注释区、frontmatter 中的上述表达式不转换；普通 `[说明](旧附件/diagram.png)` 也不转换。

## PDF 与既有章节保留验收案例

假设页面位于 `wiki/演示/页面.md`，指定目录为 `raw/示例/资料/`；成功案例的直属文件存在，`raw/示例/其他/讲义.pdf` 也存在。各行条件独立；误写固定名案例明确假设指定目录没有该文件。以下仍是人工工作流预期，不代表自动测试结果。

| 情形 | 输入或条件 | 预期 |
|---|---|---|
| 相对 raw PDF | `[讲义](<../../raw/旧目录/讲义.pdf>)`，旧文件缺失 | 匹配指定目录的同名文件，转为 `![[raw/示例/资料/讲义.pdf]]` |
| 同页多个 PDF、相同文字 | `[讲义](<raw/示例/资料/课程说明.pdf>)`、`[讲义](<raw/示例/资料/练习题.pdf>)` | 分别嵌入 `课程说明.pdf` 和 `练习题.pdf`，顺序不变，不统一为 `讲义.pdf` |
| 重复 PDF 引用 | 同页多次链接 `课程说明.pdf`，分别带 `#page=2`、`#page=5` | 每次出现均保留，文件名和各自片段不串换、不去重 |
| 未引用 PDF | raw 目录另有 `未引用附录.pdf`，页面未引用它 | 不自动插入，不新增附件或内容节 |
| 误写的固定名 | 链接目标为 `讲义.pdf`，指定目录没有该文件，只有其他一个或多个 PDF | 原表达式保留并报告，不按数量、目录顺序或第一个候选猜测改名 |
| vault 根 raw PDF | `[讲义](<raw/示例/资料/讲义.pdf>)` | 同目标仍转换语法 |
| 中文与编码空格 | `[讲义](<../../raw/旧目录/示例%20讲义.PDF>)` | 匹配实际 `示例 讲义.PDF`，保留大小写及空格 |
| 安全片段与标题 | `[下载](<raw/示例/资料/讲义.pdf#page=3> "材料")` | 片段保留；链接文字「下载」及标题「材料」只进入报告 |
| 已合规嵌入 | `![[raw/示例/资料/讲义.pdf#page=3\|讲义]]` | 字节不变，不丢后缀 |
| 缺失或歧义 | 缺失 PDF 或多个不能唯一确定的候选 | 原表达式不变，列入未决 |
| 有效其他 raw | `[讲义](<raw/示例/其他/讲义.pdf>)` | 原表达式不变并报告，不因指定目录同名而重定向 |
| 非 raw、外部或越界 | `[讲义](附件/讲义.pdf)`、外部 URL、越出 vault 的路径 | 不转换、不访问网络 |
| 解析异常 | 非法百分号编码、编码分隔符、不能安全保留的片段或嵌套链接文字 | 不转换并报告 |
| 引用式 PDF 与示例 | `[讲义][pdf]`，或代码、注释中的 PDF 表达式 | 原样保留，引用定义不变 |
| 无引用、相邻或重复章节 | 多个 `## 总结` / `## 洞察`，均无媒体或链接 | 所有标题、内容、空行及顺序保留，不新增节 |
| EOF 与子标题 | 末尾 `## 洞察` 包含 `### 子项` | 标题、子标题及内容完整保留，末尾换行状态不变 |
| 相似名与非正文标题 | `## 资料总结`、`## 洞见`、`### 总结`、代码或注释中的 `## 总结` | 全部保留 |
| 节内 Obsidian 嵌入 | 「总结／洞察」含 `![[diagram.png]]` 或 `![[讲义.pdf]]` | 保留章节，媒体可按原规则安全修复；合规 PDF 嵌入保持原样 |
| 节内 Wiki 链接 | 「总结／洞察」含 `[[示例页面]]` | 章节和链接保持原样，无需拒删报告或清理裁定 |
| 节内 Markdown 图片 | 「总结／洞察」含 `![说明](旧附件/diagram.png)` | 保留章节；安全图片转换及紧邻说明文字保留仍可执行 |
| 节内 Markdown PDF | 「总结／洞察」含可转换、缺失或不安全的 PDF 附件链接 | 保留章节；仅安全 PDF 转换，缺失或不安全引用保持原样并报告 |
| 混合引用与纯文字章节 | 「总结」有媒体而相邻「洞察」无引用 | 两节全部保留，仅允许记录的引用原位替换 |
| 只有章节与再次调用 | 有「总结／洞察」，但无引用转换、元数据修复或索引补录 | 页面、日期、索引、日志及队列不变，不新增总结或洞察 |

## 命令边界

以上 PDF 转换和章节保留规则仅属于 `update-raw-reference`，包括其既有目录子调用及 `--defer`；不改变 `enhance-wiki-content`、稀疏标签补齐或其他命令。目录分派仍沿用原规则，缺失精确 raw 配对时整页跳过，连引用、正文、元数据、日志及队列都不改。

## 整页与回归验收

在仓库外构造虚构 vault，按实际命令规则执行，不直接拿真实知识库作为公开 fixture。媒体文件可用仅供路径验证的占位文件，不进行视觉识别。

1. 创建 28 个有序图片位置：第 1–14 处为 Markdown，第 15–28 处为 Obsidian；至少一处重复同名嵌入。穿插普通正文、普通链接、代码、注释；另加视频与音频位置验证旧分支。为两种语法分别建立逐项预期，再合并为同一 manifest。
2. 验证每个原位置对应一个结果位置，28 个图片位置全部保留，视频与音频不丢失，顺序和 Obsidian 后缀不变。Markdown 可见说明每项只附加一次；不能用 `![[` 数量的增长判定媒体新增。
3. 分别覆盖 LF、CRLF 以及无末尾换行的页面。先在仓库外的临时副本上探测补丁工具是否保留换行及末尾换行状态；不保留时，真实任务应在写入前停止，不能把工具自动添加换行视为获准的引用修改。可保留时，用独立记录的原始字节 reference-replacement span 重建预期正文，对最终正文作逐字节比较；换行和末尾换行状态必须保持，所有既有章节及其他字节不格式化。核对 raw 文件前后哈希，不让验证器复用候选解析规则生成预期。
4. 第二次执行相同命令应无新转换、无重复说明；无其他维护变化时，页面日期、index、日志及队列均不变。
5. 回归无效参数、目录越界和不安全 frontmatter 的整命令零写入；单个媒体解析失败仅保留并报告该项。frontmatter 缺整块或缺标准字段时补齐七字段，已有标准及非标准字段除实质页面变化的 `updated` 外不变；索引仅补录确认未收录页面。
6. 普通模式在实际变化时运行既有日志预检并仅追加一次最终记录；`--defer` 仅完成页面和专属片段，共享 index/log 不变。索引发生变化时沿用六变量验证，不借本次扩展扩大维护范围。
