# 媒体引用修复：Markdown 规则与验证案例

本文件补充 `SKILL.md` 的 `update-raw-reference` 工作流，不是独立转换程序。所有示例均为虚构；验证产物留在仓库外，不提交真实页面、素材、manifest 或日志。

## 输入与转换规则

- 两种语法共享同一份按正文顺序建立的 manifest。记录完整原表达式及字节位置，先判断上下文再解析；不要用单个全局正则替换整篇 Markdown。
- Obsidian `![[...]]` 的图片、视频、音频扩展名及 `#fragment`、`|alias/width` 规则不变；文件名中的 `%20` 等按字面值匹配，不新增 URL 解码。
- 新增分支仅处理 inline Markdown 本地图片。支持中文、百分号编码的空格、`<...>` 包裹的含空格目标、合法反斜杠标点转义、成对括号，以及单引号、双引号或括号包裹的纯文本 title。未包裹且含未编码空格的目标按不安全语法跳过，不猜测空格属于路径还是 title。
- 先解析表达式、Markdown 标点转义、目标与可选 title，再分离未编码的 `#fragment`。对路径做一次严格 UTF-8 百分号解码；不把 `+` 当空格，不二次解码，不修改实际文件名大小写或 Unicode 形式。非法编码、编码的路径分隔符、控制字符，以及无法无损写入 Obsidian 目标的字符（如实际文件名中的 `#`、`|`、`[`、`]`）保持原样并报告。fragment 只在无需改写即可安全保留时转换，否则跳过。
- 仅接受可解释为 vault 内本地路径的目标；相对路径按页面目录解释，显式 `raw/...` 按 vault 根目录解释。失效旧路径仍可按文件名匹配指定目录，但不能越出 vault。拒绝盘符、UNC、根绝对路径及带 URI scheme 的目标；外部 URL、协议相对 URL、data URI、带未编码查询串的目标不下载、不改写。解码后再次检查这些边界。
- 按实际文件名匹配指定 raw 目录的直属文件，不搜索子目录、不推测改名。候选必须唯一且真实路径仍在该目录内；已有显式路径有效指向其他 raw 目录时保留并报告。完整正确的 Markdown 目标仍转换语法；完整正确的 Obsidian 目标为 no-op。
- 引用式图片（完整、折叠、快捷）、HTML 图片、普通链接、被外层链接包裹的图片，以及包含嵌套格式或多行 alt/title 的表达式保持原样并报告，不修改引用定义。frontmatter、代码、注释及转义后的示例不作为待转换媒体。

## 说明文字保留

纯文本 alt 经 Markdown 转义还原后，若为空或仅等于原目标文件名或一次解码后的实际文件名，则不新增说明；比较时仅忽略两端空白，不做模糊匹配。其他 alt 都视为有意义的说明。非空 title 始终保留，即使与 alt 相同，也保留其标题身份。

转换后在嵌入后立即添加 `（图片说明：…；标题：…）`；仅有一项时只保留对应字段，两项都没有时不添加括号。保留纯文本含义和内容，必要时转义 Markdown 元字符以避免意外标签、链接、嵌入或格式；遇到不能可靠解释的实体或富文本时跳过整个表达式并报告，不猜测或丢弃。不向 `|宽度/别名` 填入说明，不改变已有相邻正文。

```text
![流程概览](旧附件/diagram.png "步骤说明")
→ ![[raw/示例/资料/diagram.png]]（图片说明：流程概览；标题：步骤说明）

![diagram\.png](旧附件/diagram.png)
→ ![[raw/示例/资料/diagram.png]]
```

原来的 alt 可访问性属性与 title 悬停属性会转为可见文字，语义内容保留，呈现方式改变；不声称 Obsidian 嵌入仍有相同的 HTML 属性。

## 单项验收案例

假设指定目录为 `raw/示例/资料/`，表中成功案例所需的直属文件均存在；`missing.png` 不存在，`raw/示例/其他/diagram.png` 已存在。下表是人工工作流验收预期，不是自动化测试通过记录。

| 情形 | 原表达式 | 预期 |
|---|---|---|
| Markdown 文件名 alt | `![diagram\.png](旧附件/diagram.png)` | `![[raw/示例/资料/diagram.png]]` |
| 空 alt | `![](旧附件/diagram.png)` | `![[raw/示例/资料/diagram.png]]` |
| 中文与编码空格 | `![示例 图.png](旧附件/示例%20图.png)` | `![[raw/示例/资料/示例 图.png]]` |
| 尖括号路径 | `![](<旧附件/示例 图.png>)` | `![[raw/示例/资料/示例 图.png]]` |
| 转义括号 | `![](旧附件/plot\(a\).png)` | `![[raw/示例/资料/plot(a).png]]` |
| 成对括号 | `![](旧附件/plot(a).png)` | `![[raw/示例/资料/plot(a).png]]` |
| 仅解码一次 | `![](旧附件/literal%2520name.png)` | 匹配实际 `literal%20name.png`，不匹配 `literal name.png` |
| 加号 | `![](旧附件/a+b.png)` | 匹配实际 `a+b.png`，不匹配 `a b.png` |
| 仅说明 | `![流程概览](旧附件/diagram.png)` | `![[raw/示例/资料/diagram.png]]（图片说明：流程概览）` |
| 仅标题 | `![](旧附件/diagram.png '步骤说明')` | `![[raw/示例/资料/diagram.png]]（标题：步骤说明）` |
| 说明和标题 | `![流程概览](旧附件/diagram.png "步骤说明")` | 两项各保留一次，采用上方示例格式 |
| 括号标题 | `![](旧附件/diagram.png (步骤说明))` | `![[raw/示例/资料/diagram.png]]（标题：步骤说明）` |
| fragment | `![](旧附件/diagram.svg#overview)` | `![[raw/示例/资料/diagram.svg#overview]]` |
| 原有宽度 | `![[diagram.png\|800]]` | `![[raw/示例/资料/diagram.png\|800]]`，宽度不变 |
| 原有别名和片段 | `![[diagram.svg#overview\|概览]]` | 路径补全，`#overview\|概览` 不变 |
| 视频、音频 | `![[clip.mp4]]`、`![[sound.mp3]]` | 两者均补全 raw 路径，顺序不变 |
| 已有完整目标 | `![[raw/示例/资料/diagram.png]]` | 不变；同目标 Markdown 图片仍转换语法 |
| 别处的有效目标 | `![](raw/示例/其他/diagram.png)` | 不变并报告，不能因本目录同名而重定向 |
| 文件缺失或歧义 | `![](旧附件/missing.png)` 或多个可能候选 | 不变并报告，不猜测 |
| 外链 | `![](https://example.invalid/diagram.png)` | 不变并报告，不访问网络 |
| 引用式 | `![说明][figure]`、`![figure][]`、`![figure]` | 不变，定义不变 |
| HTML | `<img src="旧附件/diagram.png">` | 不变并报告 |
| 外层链接 | `[![说明](旧附件/diagram.png)](目标)` | 整体不变并报告 |
| 复杂说明 | `![**重点**](旧附件/diagram.png)` | 不变并报告，不丢弃格式 |
| 编码异常 | `![](旧附件/bad%ZZ.png)`、`![](旧附件/a%2Fb.png)` | 不变并报告 |
| 不可表示文件名 | `![](旧附件/a%23b.png)` | 不变并报告，不误判成 fragment |

表格中的 `\|` 是 Markdown 表格转义；构造真实正文样例时使用普通 `|`。代码区、注释区、frontmatter 中的上述表达式不转换；普通 `[说明](旧附件/diagram.png)` 也不转换。

## 整页与回归验收

在仓库外构造虚构 vault，按实际命令规则执行，不直接拿真实知识库作为公开 fixture。媒体文件可用仅供路径验证的占位文件，不进行视觉识别。

1. 创建 28 个有序图片位置：第 1–14 处为 Markdown，第 15–28 处为 Obsidian；至少一处重复同名嵌入。穿插普通正文、普通链接、代码、注释；另加视频与音频位置验证旧分支。为两种语法分别建立逐项预期，再合并为同一 manifest。
2. 验证每个原位置对应一个结果位置，28 个图片位置全部保留，视频与音频不丢失，顺序和 Obsidian 后缀不变。Markdown 可见说明每项只附加一次；不能用 `![[` 数量的增长判定媒体新增。
3. 分别覆盖 LF、CRLF 以及无末尾换行的页面。先在仓库外的临时副本上探测补丁工具是否保留换行及末尾换行状态；不保留时，真实任务应在写入前停止，不能把工具自动添加换行视为获准的引用修改。可保留时，用原始字节 span 与预期 replacement 重建预期正文，对最终正文作逐字节比较；核对 raw 文件前后哈希。不要让验证器复用候选解析规则生成预期。
4. 第二次执行相同命令应无新转换、无重复说明；无其他维护变化时，页面日期、index、日志及队列均不变。
5. 回归无效参数、目录越界和不安全 frontmatter 的整命令零写入；单个媒体解析失败仅保留并报告该项。缺失 frontmatter 才补整块，已有字段除实质页面变化的 `updated` 外不变；索引仅补录确认未收录页面。
6. 普通模式在实际变化时运行既有日志预检并仅追加一次最终记录；`--defer` 仅完成页面和专属片段，共享 index/log 不变。索引发生变化时沿用六变量验证，不借本次扩展扩大维护范围。

交付时区分「规则/案例已审阅」「人工执行样例已通过」与「自动测试已通过」，只报告实际完成的验证，不把本清单当成运行结果。
